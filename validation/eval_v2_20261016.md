# eval.py with the model interface, 2026-10-16

`eval.py` now calls `start`, `step` and `heads` from the model module instead of the sampler inside `train.py`.
The record's three Hugging Face checkpoints, rescored on one Colab A100-SXM4-40GB. Rows: [eval_v2_20261016.jsonl](eval_v2_20261016.jsonl). gFVD times 10^4.

| seed | gFVD, old eval | gFVD, new eval | AF old / new | reward precision old / new | eval s new |
|---|---:|---:|---|---|---:|
| 0 | 13.46 | 13.46 | 0.927 / 0.925 | 0.899 / 0.899 | 155.0 |
| 1 | 16.90 | 16.90 | 0.937 / 0.937 | 0.913 / 0.913 | 155.5 |
| 2 | 13.73 | 13.73 | 0.924 / 0.924 | 0.878 / 0.878 | 155.3 |

- Same numbers: on CPU the step interface gives bit-identical frames and heads to the old scan; on the GPU the scores agree to rounding. The imagined-head metrics now re-encode the generated frames from pixels and move by at most 0.004.
- Eval takes 155 s instead of 143 s (one dispatch and one decode per frame), inside the new 180 s limit.
- A second set of 2048 windows (`EVAL_SEED = 1`) gives 14.34 / 17.30 / 15.21: the window set shifts each model by 0.4 to 1.5, as much as the seed spread. 4096 windows would cut that by about 30% but double the eval time, so the protocol stays at 2048 fixed windows; every entry is scored on the same ones.
